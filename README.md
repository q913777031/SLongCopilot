# SLCopilot

采用 [MIT 许可证](LICENSE)。依赖组件保留各自的许可证。

面向 **Visual Studio 2022 17.14+** 的 AI 编程助手，使用自己的 Claude 或 OpenAI 兼容 API。当前版本 **0.7.1 预览版**（进程内扩展，由 VSIXInstaller 直接安装）：除聊天与选区编辑外，模型可以通过原生工具调用读取、搜索、创建和修改项目文件，并继续执行后续任务。尚未覆盖 Claude Code / Copilot 的全部能力。

## 当前功能

- 聊天工具窗口：聊天与智能体回答均逐字流式输出、多轮对话、停止生成；对话自动保存，可在“历史”中打开或删除。
- Claude Messages API（默认 `claude-sonnet-5-5`，adaptive thinking + 可配置 effort）和 OpenAI Chat Completions API；自定义 HTTPS Base URL、模型 ID、密钥环境变量名。
- 输入区仿 Copilot / Claude Code：左下角选择 **询问 / 智能体** 模式；旁边的模型按钮（如“Sonnet 5.5 · 中”）打开模型菜单：官方 Claude 端点列出 Opus 5.5、Fable 5.1、Sonnet 5.5、Haiku 5.5（数字键 1–4 直接选），其他配置的模型（如 GPT 配置）也在同一菜单中；“思考强度”子菜单切换 默认 / 低 / 中 / 高 / 超高 / 最高（OpenAI 兼容服务为推理模型的 低 / 中 / 高）；“更多模型”列出从服务商获取的其他模型。同一服务内切换模型或强度时对话继续，切换到其他服务配置时开始新对话。“设置”中可点击 **获取列表** 从服务商读取可用模型 ID。
- 多套模型配置；每套独立保存服务类型、地址、模型 ID、密钥变量名称、推理强度与输出限制。
- 主动附加编辑器选区或光标位置，随下一次提问发送；修改代码交给智能体模式（0.5.1 起移除了输入区的“解释”“生成”按钮与“应用审阅后的代码”菜单，解释选区用编辑器右键“解释所选代码”或 `/explain`）。
- Workspace Agent：列目录、全文字面搜索、读文件、写文件、精确文本替换，以及多轮工具执行。
- 只读/读写权限、**默认自动批准**（0.6.3 起；“设置”中可关闭，关闭后每次写入先在工具窗口显示 diff 并等待 Approve / Reject）、写入前的版本检查、原始文件备份、差异预览与撤销最近一次 Agent 运行。
- 运行时自动使用当前打开的解决方案目录作为工作区；未打开解决方案时使用手填目录或附加选区推断的目录。
- 密钥保存在 Windows 凭据管理器（按配置区分），不写入任何文件；也可继续使用环境变量。
- 读取文件支持 UTF-8（含 BOM）、UTF-16（含 BOM）以及 VS 进程的系统代码页（中文 Windows 为 GBK）；修改已有文件时保持原编码与 BOM。
- **行内补全**（默认关闭，“设置”中开启）：停顿输入约 0.4 秒后在行尾显示灰字建议，Tab 接受；可为每套配置单独指定快速的补全模型。
- 智能体可 **编译解决方案**（每次需批准）并读取 **错误列表**，用 Roslyn **查找符号 / 查找引用 / 文件大纲 / 继承与实现关系 / 项目引用关系**（0.6.3 新增 `get_hierarchy`、`get_project_graph`）；已打开的文件经编辑器修改（不弹重新加载，可 Ctrl+Z）。
- 审批时可在 **VS 差异窗口** 中查看改动，并在右侧直接删改，批准时写入你编辑后的版本。
- 斜杠命令 `/explain`、`/fix`、`/tests`、`/doc`、`/plan`、`/review`、`/debug`、`/commit`（根据 Git 改动生成提交说明，不会执行提交）、`/init`、`/remember`、`/compact`、`/export`（导出对话为 Markdown）、`/help`、`/clear`；`#file:路径` 或 `@路径` 引用文件。
- **计划模式**：模式下拉框的第三项“计划”（或 `/plan 任务`）：只读调查后给出实施计划（根因、要改的文件与成员、步骤、风险、验证方法）；输入区上方出现“▶ 按此计划执行”，点击后在同一对话中以智能体模式执行，写入与编译仍逐次批准。
- **`/review`**：审查暂存区的改动（暂存区为空时审查智能体最近一次运行的改动），按 P0 / P1 / P2 列出问题与建议，只读、不修改文件；命令后可写额外要求，如 `/review 重点看线程安全`。与 /commit 一样只读暂存区，不执行仓库配置的过滤器程序。
- **调试异常分析**：调试中断时，编辑器右键或“工具”菜单中的“SLCopilot: 分析当前异常 / 中断”读取异常、调用栈（30 帧）与当前帧局部变量，放入输入框（`/debug`），检查并可删改敏感值后再发送，不会自动发送。
- **自定义命令**：工作区中的 `.slcopilot/commands/名称.md`（兼容 Copilot 的 `.github/prompts/名称.prompt.md`）成为 `/名称` 命令；文件内容为提示模板，可用 `$ARGUMENTS` 代入命令后的文字；可选 front matter `description:` 与 `mode: ask | agent | plan`。与内置命令同名的文件被忽略。
- 项目级指令：工作区中的 `.slcopilot/instructions.md`（或 `.github/copilot-instructions.md`）自动随请求发送。
- 编辑器右键“修复此处的错误”；代码块按语言着色；状态栏显示服务商返回的 token 用量。
- **自检**：`/diag` 或“工具 → SLCopilot: 诊断”，逐项检查配置、密钥、服务连通与模型 ID、工作区、Roslyn、git、行内补全与错误列表，结果以表格显示。
- **运行日志**：`%LOCALAPPDATA%\SLCopilot\logs`，每次运行一个编号（与备份目录名相同），记录请求、重试、工具调用、审批、写入哈希，不含密钥与代码。
- **任务计划与并行读取**：多步骤任务中智能体用 `update_plan` 维护计划，气泡内显示清单与进度（原位更新）；同一回合连续的只读工具（读文件、搜索、查符号/引用、大纲、错误列表）最多 4 个并行执行，写入与编译仍逐个执行。
- **默认设置**（0.6.3；0.8.0 起默认模型改为 Sonnet 5.5）：新安装默认选中 Claude 配置（Sonnet 5.5，思考强度中，比 Opus 5.5 更快、更省 token）；已有配置不变，在模型菜单中选择即可；默认 **自动批准**智能体的写入、删除、移动、编译、测试、命令与 MCP 调用，不再弹出审批面板。写入仍校验文件版本、拒绝覆盖编辑器中未保存的修改、先备份再写，可用“撤销上次智能体运行”或检查点恢复；命令仍只能执行白名单内的程序。在“设置”中取消“自动批准…”即恢复逐次审批。逐次审批时，审批面板上的“全部批准（开启自动批准）”批准当前一项并开启自动批准，之后不再询问（与 Claude Code 的“之后不再询问”一致）；审批等待中打开 ⚡ 开关也会直接批准当前一项。工作区 MCP 配置的信任确认与恢复检查点的确认不受影响。
- **更快的智能体**（0.8.0）：提示模型把互不依赖的读取与修改放在同一回合、不整篇重写已有文件（只用编辑工具）、修改后不重读刚改过的文件；按改动清单执行时不维护任务计划，结束时每项一行汇总。验证以每次写入返回的单文件编译错误为准，只有改了被其他项目使用的公开签名、项目文件、XAML 或资源，或你要求时才编译整个解决方案；测试只在你要求时运行。
- **GPT-6 系列**（0.8.0）：官方 OpenAI 端点的模型菜单列出 GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra、GPT-6 Luna（数字键 1–4），推理强度按模型提供（Astra / 6.1 Sol 为 低–最高，Terra / Luna 另有“关闭思考”）。这些模型在 Chat Completions 中不能调用工具，智能体、询问、计划模式改走 **Responses API**：`store: false`（OpenAI 不保存对话），推理以加密形式（`encrypted_content`）随输出返回并在下一次请求中原样回传；普通聊天、摘要与行内补全仍走 Chat Completions。在 GPT-6 与其他 OpenAI 模型之间切换时开始新的智能体上下文；同系列内换模型后推理记录被拒绝时，自动去掉推理记录重试一次。详见 [docs/AGENT.md](docs/AGENT.md#openai-responses-apigpt-6-系列)。
- **Claude CLI 桥接**（0.8.0）：输入区左下角选择“Claude CLI”模式后（与询问 / 智能体 / 计划二选一，切回时先等 Claude CLI 的操作结束），SLCopilot 在 `127.0.0.1` 上以 MCP（Streamable HTTP）提供与智能体相同的工作区工具（读写、Roslyn 查符号 / 引用 / 调用层次、编译、错误列表、白名单命令），Claude CLI 注册后通过它读改代码，**文件始终由 VS 进程（devenv.exe）读写**，适用于进程透明加密的源码。需令牌，只读 / 读写可选，写入的版本校验、备份、写入保护与审批同智能体。详见 [docs/CLAUDE_CLI_BRIDGE.md](docs/CLAUDE_CLI_BRIDGE.md)。
- **可复制的输出**：回答正文（段落、标题、列表、引用）、提问文字与流式输出都可以直接选中（可跨段落）并 Ctrl+C 或右键复制；代码块与表格仍各带“复制”按钮，每条消息右上角“复制”复制整条 Markdown 原文。
- **规则与保护**（0.7.1）：
  - **写入保护**：在 `.slcopilot/settings.json` 中写 `{ "protect": ["Recipes/", "*.recipe.json", "src/Config/**"] }`，匹配的路径不能被智能体写入、删除或移动进去（自动批准开启时同样生效），工具会告诉模型把它列为“需要你处理”。不含 `/` 的模式匹配任意层的文件或目录名，以 `/` 结尾表示整个目录。该设置文件本身始终受保护；文件存在但无法读取或格式错误时本次运行**禁止所有写入**（失效即安全），用户气泡中会提示。`run_command` 执行的白名单命令不受此约束。
  - **按路径生效的指令**（兼容 Copilot）：`.slcopilot/instructions/*.md` 或 `.github/instructions/*.instructions.md`，开头写 `---\napplyTo: src/FrameworkWorkflow/**, **/*.xaml\n---` 再写规则。智能体第一次读写匹配的文件时，规则随工具结果交给模型（每份每次运行一次，工具行注明“附项目规则”）；没有 `applyTo` 的文件不自动生效。
  - **用户级指令**：`%USERPROFILE%\.slcopilot\instructions.md`，对所有解决方案生效，排在项目指令之前，冲突时以项目指令为准。
  - 工具结果中的中文不再被转义为 `\uXXXX`（此前读取带中文注释的文件时，模型看到的是转义码，token 也成倍增加）。
- **读写体验对齐 Claude Code**（0.7.0）：
  - 读取：`read_file` 带行号（`行号<Tab>内容`，与编译错误、差异中的行号一致）；超过 2,000 字符的行截短显示（该文件按部分读取处理，`write_file` 不能整体覆盖）。
  - 修改容错：模型误把行号前缀带进 `old_text` / `new_text` 时自动去掉；弯引号与直引号视为相同；整体缩进多一层或少一层时按同样差值调整新文本（都会在结果中注明）。找不到原文时附上最接近位置的当前内容（带行号），多处匹配时列出各处行号。`write_file` 拒绝带行号前缀的内容。
  - 文件在读取后被你或格式化工具改动：不写入，返回改动差异并把当前版本登记为已读，模型据此重做修改，不必整篇重读。
  - 每次写入后在对话中内联显示红绿差异（点击标题跳到改动位置）；每个工具行后显示结果摘要（如 `⎿ 第 1–200 行，共 812 行`、`⎿ +3 −1`、`⎿ 12 处匹配`），点击工具行可展开查看工具返回给模型的内容；运行结束后连续 6 行以上的工具记录折叠为一行。
  - 模型生成大段写入内容时，运行状态显示“正在生成 write_file（12 KB）”。
- **IDE 上下文**（0.7.0）：每次提问自动附带最近活动编辑器的文件、光标行与选区（选区 8,000 字符以内附原文），用户气泡中显示“⧉ 已附带…”，输入框获得焦点时输入区下方预先显示将附带的内容，点旁边的 ✕ 本次不附带；新对话的第一条消息附带 Git 分支、暂存文件与最近 5 次提交（不比较工作区文件）。智能体运行前自动保存工作区内未保存的文件（“设置”中可关闭）。
- **交互**（0.7.0）：运行中可继续输入补充要求（Enter 或“↪ 补充”），在当前步骤结束后交给模型，不必停止重来；`@` 或 `#file:` 后列出匹配的工作区文件（Tab 接受）；↑ / ↓ 找回之前发送的输入；回答中的 `路径:行号` 与 `类名.成员名` 可点击打开文件或转到定义；每条消息可“复制”；用量显示上下文占窗口的比例；输入区右侧“⚡ 自动批准”开关；把文件从资源管理器或解决方案资源管理器拖进输入框即插入 `#file` 引用；命令与文件提示可用 ↑ / ↓ 选择、Tab 或 Enter 接受，Esc 关闭；右下角“↓ 最新”回到最新消息。差异中成对的删改行会加深标出具体改动的部分；耗时 2 秒以上的工具在摘要后注明用时；思考摘要只显示第一行，点击展开。
- **按你的改动单元执行**（0.7.0）：发送“文件 / 锚点 / 操作 / 代码”格式的改动时，替换成员 → `replace_symbol`、新增成员 → `insert_near_symbol`（按“放置”的前后位置）、删除成员 → `replace_symbol` 空文本、替换片段 → `replace_between`（按起止两行原文，`within` 限定在锚点成员内）、新建文件 → `write_file`；按给定顺序原样应用，锚点不存在或有歧义时停在该单元并报告，不改总览外的代码。成员的范围包含紧贴的文档注释、普通注释与特性，不包含其上的 `#region` 与隔着空行的注释。
- **稳健性**（0.7.0）：运行因网络中断、服务端限流 / 过载（重试用尽）或流式响应中断而失败时，也出现“▶ 继续”，已完成的改动与对话都保留；请求经系统代理发送，需要认证的企业代理用当前 Windows 账户认证。
- **命令**（0.7.0）：`/init` 分析解决方案并生成或更新项目指令文件；`/remember 要求` 把一条要求追加到项目指令文件；`/compact` 立即把对话压缩为摘要。恢复检查点时对话也回退到那次运行之前，原提问放回输入框；有改动的提问气泡上直接有“↶ 回退到此前”。`/help` 列出命令、引用方式与快捷键。关闭自动批准时，审批面板显示彩色差异。
- **按改动清单读写代码**（0.6.4）：`replace_symbol(name, new_text)` 按编译器定位整段替换 / 删除成员或类型（锚点写 `类名.成员名`，重载写 `类名.成员名(int)`），`insert_near_symbol` 在声明前后新增成员；`multi_edit` 一次改同一文件多处；`edit_file` 支持 `replace_all`、可省略版本（自动用最近读到的版本）、行尾空白差异容错与未匹配提示。写入 C#/VB 后结果附带该文件的编译错误（`compile_errors`），`check_file` 不编译即可查看单个文件的诊断；`build_solution(project?)` 可只编译一个项目。
- **引用与架构**（0.6.4）：`read_symbol` 直接读取成员 / 类型源码；`get_callers` / `get_callees` 调用层次；`get_type_dependencies` 类型依赖；引用结果附所在成员；`find_symbol` 未命中时给出近似名称；`search_files` 支持整词与上下文行，`list_directory` 支持多层，`get_errors` 可按文件过滤。
- **长改动清单**（0.6.4）：每次运行默认 50 轮（“设置”中 5–100）、300 次工具调用、100 个文件、120 分钟；达到上限时出现“▶ 继续”。改动文件卡片可单独恢复某个文件（↶）或撤销本次全部改动，下一条消息会告知模型哪些文件被恢复。
- **架构关系**（0.6.3）：`get_hierarchy(name)` 用编译器语义模型给出类型的基类链、实现的接口、派生类与实现类型，或成员重写 / 实现了谁、被谁重写 / 实现（框架中的符号没有文件）；`get_project_graph()` 列出解决方案中的项目、语言、文档数与项目引用。均为只读，可与其他只读工具并行。
- **运行测试与执行命令**（0.5.0，仅智能体模式）：`run_tests` 执行 `dotnet test`，返回通过 / 失败数与失败用例的消息和堆栈（读取 TRX 结果，没有产生任何结果时不报告成功）；`run_command` 执行 **命令白名单**（“设置”中每行一条，如 `dotnet build`、`git status`）内的程序。不经过 shell（无管道、重定向、通配符与变量展开），参数逐个传递，只执行 PATH 中的 `.exe`（git 与 /commit 相同，优先使用 VS 自带的 Git），工作区内的同名程序不执行；**每条命令都要在审批面板批准**，没有“始终允许”。超时（命令默认 300 秒、测试 600 秒，最多 1800 秒）或点击停止时经 Windows 作业对象结束整个进程树；子进程不继承服务商密钥环境变量。命令对文件的修改不在备份与撤销范围内。
- **删除与移动文件**（0.5.0）：`delete_file`、`move_file` 与写入一样需先读取、逐次批准，删除前备份，撤销时按备份重新创建；移动为“先建目标再删源”，中途失败最多多出一份副本。
- **按名称查找与正则搜索**（0.5.0）：`find_files` 按通配模式（如 `*.csproj`、`src/**/*.xaml`）查找文件；`search_files` 支持正则（`regex: true`）与 `glob` 限定文件类型，每个文件最多 50 行、总计 200 行，扫描上限提高到 50,000 项。
- **批准分级**（0.5.1）：写入审批面板多一个“本次运行内始终允许此文件”：批准本次修改，并在本次智能体运行中不再询问对同一文件的写入（版本、未保存修改、编码检查与备份照常，可撤销；气泡中注明“未再询问”）。只在内存中，运行结束即失效。删除、移动、命令、测试与编译仍逐次批准。
- **已修改文件卡片**（0.5.1，仿 Copilot）：智能体回答末尾列出本次运行改动的文件与 +新增 / −删除 行数（超过 5 个可展开全部），点击一行在 VS 差异窗口中查看：左侧为修改前（只读），右侧为当前文件（可直接编辑）；已删除的文件右侧为空。卡片在运行中随写入更新，只在本次 VS 会话中显示，不随对话保存。
- **图片输入**（0.6.1）：在输入框中 Ctrl+V 粘贴截图（截图工具、PrintScreen、复制的图片文件），把图片文件拖进输入框，或点“🖼”选择文件；输入区上方显示缩略图，可逐张移除，每次最多 5 张。图片随下一次提问发送（询问、智能体、计划模式都支持），在你的气泡中显示缩略图。发送前缩放到最长边 1568 像素并编码为 PNG（过大时转 JPEG），单张不超过 3.75 MB。只附图片不写文字时，默认请模型说明图片内容并分析报错或界面问题。图片不写入保存的对话：重新打开的对话只剩文字。需要所选模型支持图片输入（Claude 5 系列与多数 OpenAI 多模态模型支持；不支持的兼容服务会返回 HTTP 400，状态栏会提示）。
- **MCP 服务器**（0.6.0）：在 `%LOCALAPPDATA%\SLCopilot\mcp.json`（用户级）或工作区 `.slcopilot/mcp.json` / `.mcp.json` 中配置 stdio 或 Streamable HTTP 的 MCP 服务器，智能体即可调用它们的工具（显示为 `mcp__服务器__工具`）。每次调用都在审批面板显示服务器、工具与参数并需批准（可选“本次运行内始终允许此工具”）；询问 / 计划模式只能调用服务器标为只读的工具。工作区配置首次使用或内容变化时需确认信任。详见下文“使用 MCP 服务器”。
- **检查点**：本次 VS 会话中每次有写入的智能体运行都可“恢复到此运行之前”（从最新一次逆序撤销，需确认）。
- **上下文自动压缩**：最近一次请求超过“上下文窗口”的 80% 时，把较早的对话总结为摘要（界面中的历史不变，对话内会提示）。
- **运行反馈与停止**：运行中“停止”按钮旁显示 `运行中 0:42 · 第 3 轮 · 5 次工具 · ↑12k ↓1.2k`；结束时在回答末尾写一行摘要（✓ 完成 / ■ 已停止 / ✗ 未完成 · 用时 · 轮次 · 工具调用 · 修改文件 · tokens），同时写入 VS 状态栏，VS 不在前台时闪烁任务栏图标。运行中在工具窗口任意位置按 **Esc** 停止，立即显示“正在停止…”。
- **节约 token**：官方 Claude 端点依靠提示缓存（缓存命中按 0.1 倍计费），不使用服务端清理工具结果（0.8.0 起关闭：每次扩大清理范围都会使整个缓存失效并按 1.25 倍重写，实测得不偿失），上下文接近窗口时自动压缩；OpenAI 兼容服务在上下文超过窗口一半后，发送时省略较早的长工具结果；超过 2000 行的文件默认只返回前 2000 行，需要时分段读取（只读了一部分的文件不允许用 write_file 整体覆盖）。长输入一律按原文发送：0.6.2 移除了“长输入自动提取关键信息”，因为压缩会丢掉核对代码所需的细节，并导致智能体不读工作区、转而向你索取材料。

## 安装与使用

1. 使用 Visual Studio 2022 **17.14 或更新版本**。安装目标清单也允许更新的主版本，但本项目尚未完成 Visual Studio 2026 实机验证。
2. 从 GitHub Actions 成功运行的 `SLCopilot-vsix` artifact 下载压缩包，解压后双击 `SLCopilot.vsix`，由 VSIXInstaller 直接安装（不经过 Visual Studio Installer，不需要联网）。也可以按下方步骤本地编译。**从 0.2.x 升级时，先在「扩展 → 管理扩展」中卸载旧的 SLCopilot**：0.3.0 是新的扩展标识，两者并存会出现重复菜单。
3. 准备你自己的 API key。推荐在下一步的“设置 → API 密钥”中粘贴并点击 **保存密钥**（存入 Windows 凭据管理器，不写文件）；也可以在 Windows 环境变量中设置 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`。不要将密钥填入环境变量名称栏。
4. 选择 **工具 → SLCopilot: 打开聊天**，点击右上角 **设置**。Claude 勾选“使用 Claude”；OpenAI 或兼容服务不勾选。
5. 设置 API 地址（例如 `https://api.openai.com/v1`），保存密钥后点击 **获取列表** 选择模型 ID（也可直接输入），然后点击 **保存配置**。
6. 在编辑器选中代码，执行 **Tools → SLCopilot: Attach Selection / Caret**。不选择文本时，附加的是插入点；不会自动附带整个文件。
7. 在输入区左下角选择模式，输入后按 Enter 或点击 **发送**。**询问**：打开了解决方案时以只读方式浏览、搜索、读取代码后回答，未打开解决方案时为纯聊天。**智能体**（默认）：可直接修改代码，每次写入前需你批准。两种模式都会自动告知当前活动文件和附加选区。
8. 智能体完成后，点击回答末尾“已修改 N 个文件”卡片中的文件，在差异窗口中查看改动。

首次云端构建受 GitHub 账户额度限制未能启动，当前请使用已生成的本地 VSIX 或自行编译；云端 artifact 需要成功运行工作流后才会出现。

0.3.1 补齐了 VS 包的 DLL CodeBase 注册，修正 0.3.0 安装包无法明确定位私有扩展程序集的问题。0.3.0 可直接升级到 0.3.1，安装前关闭所有 VS 窗口。菜单仍不出现时，检查扩展是否启用，并收集以 `devenv /log` 启动后的 ActivityLog；包检查不能代替 IDE 加载验收。

## 使用 MCP 服务器

配置文件格式兼容 VS Code / Visual Studio（`servers`）与 Claude Code（`mcpServers`），允许注释与尾逗号：

```jsonc
{
  "servers": {
    // stdio：命令不经过 shell，按 PATH 查找 .exe；npx 等 .cmd 脚本需写成 cmd /c
    "fs": { "command": "cmd", "args": ["/c", "npx", "-y", "@modelcontextprotocol/server-filesystem", "D:\\docs"] },
    "sql": { "command": "C:\\tools\\sql-mcp.exe", "env": { "SQL_PASSWORD": "${env:SQL_PASSWORD}" }, "timeout_seconds": 60 },
    // HTTP：必须是 https（本机地址除外）；密钥写成 ${env:变量名}，不要直接写进文件
    "docs": { "type": "http", "url": "https://mcp.example.com/mcp", "headers": { "Authorization": "Bearer ${env:DOCS_TOKEN}" } }
  }
}
```

1. 用户级 `%LOCALAPPDATA%\SLCopilot\mcp.json` 直接生效；工作区配置（先找 `.slcopilot/mcp.json`，没有再找 `.mcp.json`）第一次使用或内容变化时弹窗列出命令与地址，确认信任后才启动。拒绝后本次 VS 会话不再询问。两处有同名服务器时用户级优先。
2. 服务器在**新对话的第一次智能体运行**时启动，工具列表在该对话内固定（Claude 5 要求工具定义在对话内不变）；修改配置或服务器新增工具后，点击“新对话”生效。已有内容的对话（含打开的历史对话）不启动 MCP。
3. 每次调用都需批准；批准时可选“本次运行内始终允许此工具”。工具说明与结果作为不可信数据交给模型；结果超过 50,000 字符时截断，图片只注明类型。
4. 单个服务器启动失败（30 秒握手超时、程序找不到、HTTP 错误）只在回答中提示，不影响其他服务器与本次运行。调用超时默认 120 秒（`timeout_seconds`，最多 1800）。
5. stdio 服务器进程放入 Windows 作业对象：新对话、打开历史对话或关闭 VS 时结束整个进程树；子进程不继承服务商密钥环境变量。
6. “工具 → SLCopilot: 诊断”显示读取到的配置、服务器与信任状态。

## 配置多个模型

1. 输入区左下角的模型下拉框选择已有配置；首次提供 OpenAI、Claude，并将旧版设置作为 **Imported settings** 导入。
2. 点击 **设置 → 新增配置** 复制当前配置。填写 **模型配置名称**，例如 `Claude 编程` 或 `OpenAI 日常`。
3. 设置该配置的服务类型、API 地址、模型 ID（可点 **获取列表**）、密钥和 Claude 推理强度，点击 **保存配置**。
4. 密钥按配置分别保存在凭据管理器；未保存密钥时回退到环境变量名称。
5. 保存后直接在输入区下拉框切换。切换会先保存当前有效编辑，并启动新的对话；运行任务时下拉框禁用。当前配置无效或磁盘保存失败时会保留原选择并提示原因。
6. **删除配置** 删除当前配置，至少保留一套。重启 VS 后恢复上次选中的配置。

配置保存在 `%LOCALAPPDATA%\SLCopilot\profiles.json`，不含密钥；原 `settings.json` 保留。“获取列表”调用服务商的 `GET /models`，部分兼容网关不提供该接口，此时直接输入模型 ID。

## 像编程 Agent 一样读写代码

1. 完成上面的服务配置，先保存编辑器中未保存的文件。
2. 打开解决方案即可：运行时自动把解决方案目录作为工作区（显示在“设置 → 工作区目录”）。未打开解决方案时，输入项目根目录的绝对路径，或先附加选区，插件会尝试定位最近的 Git / solution 根目录。
3. 输入任务，例如：`阅读项目中的服务类，为 OrderService 增加参数校验，并创建对应单元测试文件。`
4. 模式选择 **智能体**（默认）后发送即可修改文件；选择 **询问** 时只读，也不会替换“撤销上次智能体运行”的记录。
5. 模型每次调用 `write_file` / `edit_file` 时，工具窗口出现审批面板，显示该次修改的 `-/+` 差异：**Approve** 后才落盘，**Reject** 则不写入并告知模型不要重复。等待审批期间点击 **Stop generation** 视为未批准。展开 **Agent activity and changed files** 可查看工具调用、回答、修改文件列表、备份路径和差异预览。
6. 同一工作区与服务配置下，可以输入后续要求再运行；工具对话保留在内存中。**New chat** 清空对话；切换工作区、服务、模型或密钥变量也会重置 Agent 对话。
7. 如需恢复，点击 **Undo last agent run**。仅恢复当前会话中最近一次 Agent 运行的修改；文件后来被你修改时会拒绝覆盖。开始下一次 Agent 运行会替换此按钮对应的运行记录，旧备份仍保留在磁盘。

已在编辑器中打开的文件经编辑器修改并保存，不弹“重新加载”，可 Ctrl+Z；未打开的文件直接写磁盘。目标文件有未保存改动时拒绝写入（智能体读取时能看到未保存内容）。**Stop generation** 在工具边界停止执行；已经完成的写入保留。多文件操作不是一个原子事务，失败或撤销中断时可能只完成部分文件，界面与备份清单会保留剩余记录。

智能体模式下可调用 `build_solution` 编译解决方案（**每次需你批准**，因为会执行生成事件），并通过 `get_errors` 读取错误列表，据此继续修复；用 `run_tests` 运行测试、`run_command` 执行白名单内的命令（**每次需你批准**）。没有 shell：白名单外的程序、管道与重定向都不能执行。Agent 回答逐字流式显示；工具调用只在完整收到并校验该回合后才执行，中断的流不会执行任何工具。

边界、忽略规则与限制见 [Agent 架构](docs/AGENT.md)。

接口示例：

| 服务 | Base URL | 密钥变量名 | 协议 |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `OPENAI_API_KEY` | `/chat/completions` |
| Claude | `https://api.anthropic.com/v1` | `ANTHROPIC_API_KEY` | `/messages` |
| 兼容服务 | 服务商提供的 HTTPS API 根路径 | 自定义，例如 `MY_AI_API_KEY` | `/chat/completions` |

默认模型只是可编辑的起点，模型是否可用取决于服务商与账户。OpenAI 兼容服务需支持 SSE、`max_completion_tokens` 和 Bearer 认证；Agent 还需要原生 function calling（`tools`、`tool_calls`、`tool_call_id`）。当前不支持只接受 `max_tokens` 的旧兼容网关、Azure 特有部署路径/认证或 OpenAI Responses API。

## 数据与限制

- 普通聊天上传提示词、附加选区及保留的对话。切换模型配置、保存新的服务参数时会清空对话上下文；Agent 对话也会随服务配置切换自动重置。
- Agent 上传请求读取的文件内容、搜索结果与工具对话；仅计算版本哈希时不会上传额外文件全文。写入备份保存在 `%LOCALAPPDATA%\SLCopilot\backups\<run-id>`，包含原始代码，需自行管理保留时间。
- 模型配置保存在 `%LOCALAPPDATA%\SLCopilot\profiles.json`，仅保存服务参数与环境变量名称；旧 `settings.json` 用于首次迁移并保留。
- 对话保存在 `%LOCALAPPDATA%\SLCopilot\conversations\<id>.json`（含提问、回答与 Agent 工具对话中读取的代码片段），最多保留 100 个，超出删除最旧的。
- 提问与附加选区不再限制字数（选区所在文件最多 200 万字符）；上限取决于所选模型的上下文窗口，超出时服务端返回 HTTP 400/413，状态栏提示新建对话或减少附加内容。普通聊天保留最近 10 轮历史，每轮都会重新上传，长输入会增加费用。
- 单次模型请求超时 10 分钟。输出上限：已知支持 128K 输出的 Claude 模型（Claude 5 系列、Opus 4.6+ 等）默认 64,000 tokens，其他模型与服务保持 16,000（OpenAI 兼容服务最多 32,768）。智能体单文件上限默认 1 MiB（“设置”中可改为 16 KiB–32 MiB），更大的文件用 `read_file` 的 `start_line` / `line_count` 分段读取（最大 32 MiB）；搜索最多 200 条结果，目录最多列出 1000 项。智能体每次运行最多 120 分钟（含等待审批）、50 回合、300 次工具调用、100 个修改文件；达到上限时已完成的改动与对话都保留，发送“继续”即可接着做。
- Claude 5 系列要求历史中的 thinking 块原样回传、且 system 与工具定义在对话内不变；Agent 历史只追加，读写模式写在每次的用户消息里。Effort 留空时不发送 thinking/effort，用于不支持 adaptive thinking 的旧模型。
- 仅官方 `api.anthropic.com` 端点会额外发送 prompt caching 与 Claude 5 系列的服务端拒答回退（`fallbacks: "default"` + beta 头）；第三方网关不发送。拒答（refusal）和截断的回答不会执行工具。上下文超限时需新建对话；不会丢弃未配对的工具消息后继续请求。
- 对话以气泡显示，回答按 Markdown 子集渲染（标题、列表、引用、代码块、表格、粗体/斜体/行内代码/链接）；流式输出期间先显示纯文本，结束后再渲染。停留在底部时自动跟随新内容，手动向上滚动后暂停跟随；代码块带“复制”按钮；链接可点击，只打开 http/https 地址。输入框 Enter 发送、Shift+Enter 换行。界面为中文。代码块按语言着色（C#、C/C++、Java 系、JS/TS、Python、SQL、Shell、JSON、XML/XAML），配色随 VS 深浅主题。
- 代码块带“插入”（插入到最近活动编辑器的光标处，有选区时替换选区，可 Ctrl+Z 撤销）与“复制”按钮；等待首个回复时气泡显示“思考中…”。
- 编辑器右键菜单提供“SLCopilot: 解释所选代码”、“附加选区 / 插入点”和“修复此处的错误”（读取错误列表中当前文件光标附近的错误，以智能体模式修复）。
- 遇到连接失败或 HTTP 408/429/500/502/503/504/529 时自动重试（遵守 Retry-After，上限 20 秒；否则 1、2、4 秒退避，最多 4 次），状态栏显示重试进度。只在收到成功响应前重试，不会重复接收已生成的输出。
- API 密钥读取顺序：Windows 凭据管理器中该配置的密钥（目标名 `SLCopilot:profile:<配置 Id>`）→ VS 进程环境变量 → 用户级 → 系统级环境变量。删除配置时一并删除其凭据。
- 无 BOM 且不是合法 UTF-8 的文件按 VS 进程的系统代码页解码；模型写入的内容含该编码无法表示的字符（如 GBK 文件中的 emoji）时拒绝写入，不做有损替换。
- 行内补全默认关闭；开启后，停顿输入时把光标前约 6,000、后约 2,000 字符的代码发送给当前配置的服务（只针对工作区策略允许的源文件，`.slcopilotignore` 排除的文件不发送）。不重试；认证失败、限流或网络错误后暂停 60 秒。只在行尾（光标后只有空白或闭合符号）补全，IntelliSense 列表打开时不补全。
- 状态栏右侧的 token 用量来自服务商返回值（OpenAI 仅官方端点请求流式用量）；不做本地估算。
- `/commit` 只读取暂存区（不比较工作区文件，因此不会执行仓库 `.gitattributes` 配置的过滤器程序），以固定参数调用 git（禁用外部 diff、textconv、fsmonitor、签名显示）；diff 超过 400,000 字符时截断并注明。优先使用 PATH 中的 git，否则用 VS 自带的 Git。请先 `git add` 要提交的文件。
- 运行日志按 5 MB 换文件，保留 14 天、最多 30 个文件；写日志失败不影响功能，自检中会显示。
- 上下文窗口：Claude 配置默认 1,000,000 tokens（当前 Claude 5 系列与 Opus 4.6+ 均为 100 万）；点“获取列表”时按服务商 `/v1/models` 返回的 `max_input_tokens` 自动填入（仍是自动值时；手动改过的不动）。OpenAI 兼容服务默认 200,000，需按模型文档填写；0 关闭自动压缩。服务商未返回用量时按每 3 个字符 1 个 token 估算（偏保守）。
- 智能体压缩把整段历史换成摘要：官方 Claude 端点使用服务端按需压缩（beta `compact-2026-09-04`，摘要块原样回传），其他服务由本地生成摘要；都不保留旧回合原文，避免 Claude 5 系列拒绝失效的思考记录。官方端点上对 Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 设置“失效的思考记录直接丢弃”（beta `thinking-binding-controls-2026-08-01`）；其他端点遇到 400 时去掉历史中的思考记录后重试一次。聊天历史仍保留最近 2 轮原文。压缩失败时继续使用完整历史并提示。
- 检查点只在当前 VS 会话内有效；VS 重启后需按备份目录（与日志中的运行编号相同）手动恢复。
- MCP 只支持工具（tools），不支持 resources、prompts、sampling 与 OAuth 登录；HTTP 不打开服务器主动推送的 GET 流。没有通用 shell：命令只能执行“设置 → 智能体命令白名单”中的程序，每条都需批准；白名单为空时不能执行任何命令或测试。`run_tests` 只支持 SDK 风格项目（`dotnet test`），不调用 VS 测试资源管理器。
- 本机已完成编译和模拟 HTTP 测试；尚未完成真实密钥联调、Visual Studio 安装和 UI 操作验收，详见 [验收清单](docs/VALIDATION.md)。

## 开源发布与敏感信息

- API 密钥通过 Windows 凭据管理器或环境变量配置；文档和测试只使用占位值。
- 不提交真实 `.env`、证书私钥、MCP 令牌、本机服务配置、对话、代码备份或运行日志。可分享的配置示例应使用 `.example` 文件名和占位符。
- `.gitignore` 已排除本机测试报告、构建包和诊断产物。不要直接压缩整个工作目录发布；旧安装包和 PDB 可能保留个人发布者名称或本机路径，应从清理后的源码重新构建。
- 清理当前文件不会删除 Git 历史中的个人邮箱或旧内容。公开仓库前，需要另外确认发布历史的处理方式，并扫描实际发布的文件和历史。
